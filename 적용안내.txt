아가애봄 카카오챗봇 구현 패키지
작성 기준: 2026-11-17 (한국시간)

1. 구현된 내용

원본 엑셀의 57개 블록 ID를 유지하고 18개 확장 블록을 더했습니다.
총 75개 중 기본 활성 69개, 비활성 6개입니다.
비활성: 임시 휴진 C-04, 챗봇 내 예약 접수 H-02~H-06.
기존 11개 블록은 원문·이미지를 보존하는 연결안입니다. 패키지에 들어 있는
기존 블록의 설명은 시연 및 후속 메뉴용이며 기존 채널 문구를 재현한 것이 아닙니다.

PDF 4종의 설명을 질문별로 재구성한 사전 작성 응답 방식입니다.
생성형 AI가 새 의료 답변을 만들지 않습니다. 새 질문은 상담 또는 메뉴로 안내합니다.
임신율·성공률 수치, 개별 증상 판단, 복약·용량·시술 적합성 판단은 제공하지 않습니다.
난자 채취 금식, 이식 후 직장 복귀 등 병원별 지침이 없는 질문은 확인 경로를 제공합니다.

조무성: 현재 카카오채널의 상담직원 전환 버튼(action: operator).
유지희: 사용자가 제공한 http://talk.naver.com/WFMOB5L 링크.
카카오 상담 전환은 채널의 상담 담당자에게 연결하는 기능입니다.
특정 원장님 계정으로 자동 배정하거나 원장님의 실시간 응답을 보장하지 않습니다.
담당자가 조무성 원장님 상담 요청을 구분하는 운영 절차가 필요합니다.
미리보기의 카카오 전환은 설명 창으로 시연하며 실제 상담을 만들지 않습니다.

2. 파일

index.html: 서버 없이 파일을 열어 확인 가능한 독립 미리보기.
content.json: 75개 블록의 원고·연결·발화·출처·확인사항. 운영 원고의 기준 파일.
블록원고.csv: 병원·대행사 검수용 전체 원고. UTF-8 BOM, 엑셀로 열기 가능.
core.mjs: 미리보기와 실제 스킬이 함께 사용하는 질문 분기와 카카오 응답 생성기.
server.mjs: Node.js 스킬 서버. POST /skill 또는 /skill/E-04 등.
worker.mjs, wrangler.jsonc: Cloudflare Workers에 올릴 수 있는 대체 서버.
Dockerfile: Node 서버 컨테이너 구성. 운영 시 SKILL_TOKEN 필요.
카카오응답예시.json: 각 논리 블록에 대한 카카오 v2.0 응답 예시.
블록연결목록.csv: 블록별 스킬 URL 경로와 등록할 발화·후속 버튼.
test/: 문답·안전 분기·버튼·출력 한도·HTTP 검증.

content.json·CSV·응답예시 JSON은 카카오 봇 전체를 가져오는 공식 백업 형식이 아닙니다.
카카오 관리자센터의 블록 생성, 스킬 등록 및 연결은 아래 순서로 적용해야 합니다.

3. 내 PC에서 확인

독립 미리보기: index.html을 더블클릭합니다.
서버 실행: Node.js 22 이상에서 패키지 폴더를 열고 아래 명령을 실행합니다.

  node server.mjs

  미리보기: http://127.0.0.1:8787/
  상태 확인: GET http://127.0.0.1:8787/health
  스킬: POST http://127.0.0.1:8787/skill

별도 npm 패키지 설치나 AI API 키가 필요하지 않습니다.
  npm test
로 테스트를 실행합니다.
미리보기 자유입력은 브라우저 메모리에서만 처리합니다.
HTTP 서버는 실제 카카오 요청 본문을 처리하지만 저장소·대화 로그·분석 도구를 사용하지 않습니다.

4. 실제 HTTPS 서버 올리기

아직 호스팅 계정에 배포하거나 실제 카카오채널을 수정하지 않았습니다.
localhost URL은 카카오 스킬 서버로 등록할 수 없으므로 외부 HTTPS 호스팅이 필요합니다.

방법 A — Node/Docker 지원 호스팅

이 폴더를 호스팅 서비스에 올리고 node server.mjs를 시작 명령으로 설정합니다.
운영 환경변수:
  HOST=0.0.0.0
  PORT=호스팅 서비스가 지정하는 포트 (기본 8787)
  NODE_ENV=production
  SKILL_TOKEN=무작위 24자 이상의 비밀값

비밀값은 호스팅 환경변수와 카카오 스킬 헤더에만 넣습니다.
URL 쿼리, CSV, 엑셀, 소스코드에는 넣지 않습니다.
config.example.json을 config.json으로 복사해 실제 카카오 블록 ID를 매핑할 수 있습니다.
Docker를 사용한다면 config.json을 컨테이너에 추가 마운트하거나 복사해야 합니다.

방법 B — Cloudflare Workers

Node.js와 공식 Wrangler CLI가 있는 환경에서 Cloudflare 계정에 로그인합니다.
  npx wrangler login
  npx wrangler secret put SKILL_TOKEN
  npx wrangler deploy
비밀값은 명령의 입력 프롬프트에 넣습니다. 소스·명령행 인수에 쓰지 않습니다.
worker.mjs는 config.json의 블록 ID 매핑을 사용하지 않습니다.
기본 메시지 버튼과 extra.targetBlock, 폴백 스킬 연결 방식으로 작동합니다.
wrangler 설정에서 Workers 관측 로그를 꺼두었습니다.
실제 배포 계정·요금·도메인 설정과 배포 확인은 해당 호스팅 운영자가 수행해야 합니다.

5. 카카오 관리자센터 연결 순서

① 기존 봇과 연결된 운영·개발 채널을 확인하고 현재 설정을 보관합니다.
② 개발 채널에서 먼저 테스트합니다. 기존 8개 메뉴 카드와 11개 운영 블록은 삭제하지 않습니다.
③ 스킬에 HTTPS주소/skill을 등록하고 응답 형식 v2.0을 사용합니다.
   요청 헤더: x-skill-token = 호스팅 환경변수 SKILL_TOKEN과 같은 비밀값.
   사용자 발화는 userRequest.utterance, 버튼 목적지는 action.clientExtra.targetBlock으로 받습니다.
④ 폴백 블록에 이 공통 스킬을 연결하고 응답에 ‘스킬데이터 사용’을 설정합니다.
   기존 폴백의 고정 안내가 스킬 응답을 가리지 않도록 구성합니다.
⑤ 각 신규 블록을 등록하는 경우 블록연결목록.csv의 경로를 사용합니다.
   예: E-04 → HTTPS주소/skill/E-04, B-07 → HTTPS주소/skill/B-07.
   이 방식은 논리 블록 ID와 카카오의 실제 블록 ID가 달라도 사용할 수 있습니다.
   또는 공통 /skill에 모두 연결하고 config.json에 실제 ID를 매핑합니다(Node 방식).
⑥ 모든 신규 블록의 원고와 후속 버튼은 카카오응답예시.json에서 확인할 수 있습니다.
   기본 버튼은 action:message, messageText:버튼명, extra:{targetBlock:논리ID}입니다.
   메시지가 폴백 또는 공통 스킬로 도달하도록 발화·기존 매칭 충돌을 확인합니다.
   안정적인 직접 이동이 필요하면 실제 카카오 blockId를 매핑해 action:block을 사용합니다.
⑦ 기존 카드에는 후속 블록으로 이동하는 버튼만 추가합니다.
   원본 이미지와 원문을 이 패키지의 시연용 설명으로 교체하지 않습니다.
   기존 B-01→B-02~07, E-01→E-02~07·PGT·불편감, F-01→F-02~05,
   G-01→G-02~04, H-01→예약·상담 안내 등을 연결합니다.
   상세 구성은 엑셀 04 탭의 노란 수정 의견과 블록연결목록.csv를 참조합니다.
⑧ 채널 관리자센터에서 1:1 채팅 또는 상담톡을 켭니다.
   B-08의 operator 버튼을 실제 모바일 카카오톡에서 눌러 전환 여부를 시험합니다.
   운영 채널과 개발 채널 모두의 상담 설정을 확인합니다.
⑨ B-09 버튼의 네이버 톡톡 연결을 실제 기기에서 시험합니다.
   제공된 링크는 그대로 반영했습니다. 로그인·외부 서비스 상태는 실제 기기 확인이 필요합니다.
⑩ 원장님 원고 검수와 시간표 확인 후 스킬과 관련 시나리오를 함께 배포합니다.
   챗봇 스킬 호출은 통상 5초 이내 응답이 요구됩니다. 이 구현에는 외부 AI 호출이 없습니다.

스킬 서버만 연결해도 카카오의 모든 기존 발화가 자동으로 이 서버를 통과하는 것은 아닙니다.
기존 고정 블록이 먼저 매칭하면 해당 고정 응답이 실행됩니다. 자유입력용 폴백과
의료 판단·개인정보 관련 발화가 이 스킬로 들어오도록 관리자센터에서도 라우팅을 확인합니다.
서버의 안전 분기는 스킬에 도달한 요청에 적용됩니다.

6. 병원 확인이 필요한 사항

가. 진료시간 불일치
  팜플렛: 월·화·목·금 08~19 / 수 08~16:30 / 점심 12:30~13:30
  공식 홈페이지: 월·수·금 08~19 / 화·목 08~17 / 점심 13~14
  홈페이지 연결 네이버 예약: 월·수·금 08~19 / 화·목 08~16:30 / 점심 12:30~13:30
  챗봇의 C-01에는 확정 시간표 대신 확인 경로를 넣었습니다.
  원본 엑셀의 기존 운영 원고는 ‘유지’로 표시하고 작성자 칸에 불일치를 남겼습니다.
  시간표를 확정한 뒤 기존 채널 카드와 서버 원고를 함께 맞춰주세요.

나. 상담시간과 부재중 응답
  진료시간과 상담 운영시간은 별개입니다. 상담 요일·시간·휴일·응답 기한은 미제공입니다.
  특정 시각의 응답을 약속하거나 시간에 따라 자동으로 부재중으로 분기하지 않습니다.
  S-04는 필요 시 연결할 수 있는 문구이며 실제 운영시간 판정 기능은 켜져 있지 않습니다.

다. 검사·시술 준비
  금식 시작 시각, 물·복약, 보호자 동반, 귀가·운전, 이식 후 출근·운동 등의 병원 지침.
  검사별 결과 소요시간, 이전 검사 인정기간, 초진·재진 체류시간, 내원 횟수.
  해당 내용은 임의 수치 없이 상담으로 연결하는 원고로 작성했습니다.

라. 개인정보·예약 접수
  이번 구현은 네이버 예약과 병원 전화로 연결합니다. 이름·연락처·희망일시를 받지 않습니다.
  H-02~H-06은 모두 H-01로 우회하며 완료·확정 메시지를 보내지 않습니다.
  챗봇 내 접수를 추가하려면 병원에서 목적·보유기간·책임자·동의 원문·접수 처리 방법을
  확정해야 하고, 그에 맞는 실제 수집·삭제·접수 기능을 별도로 구현해야 합니다.
  카카오 및 네이버 상담 서비스의 대화 보관·삭제 정책은 별도입니다.
  호스팅 프록시·WAF·APM에 요청 본문이나 상담 내용이 기록되지 않도록 운영자가 설정합니다.

마. 최종 원장 검수
  10_검수체크리스트의 확인 칸은 대신 승인하지 않았습니다.
  03_담당자_아이디어의 질문은 실제 환자 로그가 아닌 제안입니다.
  원본 02 탭 5행의 금식 문구는 서식 예시이므로 런타임에 포함하지 않았습니다.
  원본의 흰색·회색 셀, 수식, 탭, 기존 서식은 보존했습니다.
  추가 블록은 원본에 임의로 행을 넣지 않고 CSV·JSON에 수록했습니다.
  02 탭 리스트형 원고는 30자 제목이고, 개별 리스트 항목은 04 탭 의견과 JSON에 있습니다.
